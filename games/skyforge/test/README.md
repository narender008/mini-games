# Skyforge Tycoon tests

Run from this folder (`npm install` once, then `npx playwright install chromium` if no Chromium is around):

- `npm test` runs everything below and exits non-zero on any failure.
- `npm run smoke` (`smoke.test.cjs`): clean load (no console errors, 404s or network calls), a non-blank animated title, the hook's `state()` and `content()` shape and the research tree's links, title to profile to colony by real clicks, a building placed from the palette and finished, every panel (research, sky chart, fleet, pause, settings), a research started by clicks and completed, the speed buttons, a raid with its ability buttons and a storm, every preset colony running a day, the won screen and back, and sound held until the first gesture.
- `npm run input` (`input.test.cjs`): mouse place, right-click cancel, select, drag pan and wheel zoom; keyboard pan, zoom, panel keys, speed keys, pause, Esc; the raid abilities on Q W E T; touch tap-to-place, one-finger pan and pinch zoom on a phone; the HUD fitting phone portrait and landscape.
- `npm run save` (`save.test.cjs`): autosave, close-and-reopen restores the colony, export + import keeps the sim hash, three independent profiles, a truncated, tampered or junk newest slot falling back to the older one, garbage in every key still giving a working title, every migration from `save.fixture(v)`, future versions left untouched and refused on import, export/import through the Settings buttons, and nothing written under plain `?debug`.
- `npm run bot` (`bot.cjs`): the economy bot plays fresh colonies on several seeds through the action API only (`lib/policy.cjs` reads costs and recipes from `content()`), with a raid and a storm forced on a schedule. Fails unless every colony comes through both, sends an expedition, claims a second island and lights the Skyforge (scene `won`) inside 20 to 240 game minutes (the build's budget: 4 h of game time). Also runs the game's own `__sf.auto` for comparison. Writes `out/economy.md` and `out/economy.json`. `SF_SEEDS`, `SF_MIN_WINS`, `SF_GOAL_MIN`, `SF_GOAL_MAX`, `SF_RAID_AT`, `SF_STORM_AT`, `SF_TICK`, `SF_SKIP_AUTO` tune it.
- `npm run perf` (`perf.cjs`): the `late` preset plus `stress()` (12 islands, 400 buildings, 30 ships, 12 pirates) at 3x with the camera moving, calm and then in a storm and raid, on the high and low tiers: frame-interval p95, game JS per frame, and sim cost per game minute. CI has no GPU, so the ceilings (low tier p95 70 ms, JS p95 25 ms, sim 150 ms per game minute) are regression guards; the 60 fps budget is reported as warnings and enforced with `SF_PERF_STRICT=1` on a GPU machine. Writes `out/perf.md`.
- `npm run shots` (`screenshots.cjs`): every screen at 1280x720 plus phone landscape and portrait into `out/screens/` with an `index.html` contact sheet. `SF_SHOTS_DIR` copies them elsewhere.

What the suite assumes about the game (the `window.__sf` hook, button ids, keys, save keys) is in `lib/game.cjs`; the contract is the header of `../src/main.js`. `SF_ROOT=<dir>` serves another checkout instead of this repository, and `SF_CHROMIUM=<path>` picks the browser. Chromium always runs muted.

CI: `.github/workflows/skyforge-tests.yml` runs `npm test` on pull requests that touch `games/skyforge/` and uploads `out/` as an artifact.
